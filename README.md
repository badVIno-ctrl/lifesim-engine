# Симулятор мира · v13.1 (PWA)

Текстовый симулятор жизни одного человека. Проза — от рассказчика, числа — от движка.
Играется в браузере на ПК и на телефоне, ставится как приложение, работает без сервера,
без аккаунтов и **без чужих API-ключей**.

Два вида одной игры: **2D-сцена с колодой действий** для тех, кто пришёл играть, и
**чистый текст** для тех, кому картинка мешает.

## Запуск

```bash
npm install
npm run dev
```

Откройте http://localhost:5173 и нажмите «Играть сразу». Ключ не нужен: по умолчанию
рассказчиком работает свой движок в коде. Ключ модели вводится в «Настройках», если
хочется живой прозы вместо считанной.

Никаких docker, миграций, `.env`, отдельной сборки клиента и сервера, глобальных утилит.
`npm run dev` поднимает и клиент, и LLM-прокси — прокси живёт middleware'ом внутри Vite
(`server/vite-plugin-llm-proxy.ts`) и нужен только тем, кто играет с моделью.

### Продакшн

```bash
npm start
```

Сборка + запуск одной командой (Hono раздаёт `dist/` и тот же прокси) — http://localhost:5173.
Порт меняется переменной `PORT`. Сервер слушает только свою машину; чтобы позвать игроков
из локальной сети, скажите это явно: `HOST=0.0.0.0 npm start`.

## Два рассказчика

Ход всегда идёт через одно и то же ядро: `applyDelta` — единственное место, где меняются
числа. Отличается только тот, кто предлагает изменения и пишет сцену.

| | Свой движок (по умолчанию) | Модель по ключу |
| --- | --- | --- |
| Ключ, сеть, токены | не нужны | нужны |
| Проза | собирается из фразовых банков: суше, но без вранья | живее и разнообразнее |
| Числа | видит состояние целиком и потому не выдумывает | видит только рендер состояния |
| Требования календаря | отрабатывает все, всегда | отрабатывает, если поняла |
| Воспроизводимость | полная: тот же ход даёт тот же результат | нет |
| Отклонённые дельты | ноль на сотнях ходов эталонного прогона | бывают, и это нормально |

Переключается в «Настройках» одним выбором. Партии совместимы: одну и ту же можно вести
то так, то так.

### Как устроен свой движок

```
src/narrator/
  rng.ts       детерминированная случайность: зерно из состояния, а не из времени
  flavor.ts    «вкус» мира по описанию сеттинга: город, порт, село, промысел, дорога + общий слой
  intent.ts    разбор реплики игрока по корням слов: 25 намерений плюс «своё»
  resolve.ts   модель исхода: константы, навык, тело, отношение, давление мира, один бросок
  phrases.ts   фразовые банки: ни одной цифры, ни одного названия ступени лестницы
  plan.ts      что случилось: дельта для ядра и биты для прозы
  narrate.ts   сборка абзацев: где ты → что сделал и чем это стоило → что ответил мир → чем кончилось
  index.ts     рассказчик целиком плюс колода действий для 2D
```

Универсальность держится на двух приёмах. Мир опознаётся по словам описания, а не по списку
разрешённых миров: незнакомому сеттингу достаётся общий слой, и он работает. Цены и заработки
считаются от `economy.anchors` пака, а не от вшитых чисел: один и тот же движок торгует
в грошах, кронах и пайках выдуманной орбитальной станции.

## 2D-режим

```
src/ui/scene2d/
  compose.ts   состояние → композиция сцены: погода, свет, силуэты, фигуры, попадания мышью
  palette.ts   палитра по часу суток и по тому, внутри вы или на улице
  paint.ts     кисть: единственный файл, который знает про canvas
  Scene2D.tsx  жизненный цикл кадра: размеры, кадры, курсор, доступность
```

Картинок в проекте нет ни одной. Сцена рисуется линиями из состояния, поэтому работает
оффлайн, весит ноль байт и подходит любому миру, который придумает игрок. По человеку
в кадре можно нажать — это ход. Колода действий собирается из состояния и живёт в подвале,
чтобы играть можно было одной рукой и ничего не печатая. Движение уважает
`prefers-reduced-motion`, скрытая вкладка кадры не рисует.

## Настройка вкуса партии

Правила живут **в состоянии партии**, а не в настройках приложения: две партии идут по разным
правилам, и экспорт везёт правила с собой. Три пресета на виду, пять ручек в свёрнутом блоке;
крутнул ручку — ярлык сам стал «Своё».

| Ручка | Что меняет |
| --- | --- |
| Давление мира (1–5) | скорость эскалации просрочки, настойчивость движка, цену ошибки |
| Длина сцены | сколько игрового времени занимает ход |
| Правило смерти | смерть или необратимый шрам вместо неё |
| Остывание отношений | сколько игровых дней без встречи стоят ступени отношения |
| Настойчивость с вопросами | через сколько ходов движок сам требует новую неясность |

Все чтения настроек идут через `tuningOf` из `src/tuning.ts` — разбор, который не падает
ни на `undefined`, ни на старом сейве, ни на мусоре.

## Установка как приложения

- **Android / Chrome:** меню → «Установить приложение».
- **iOS / Safari:** Поделиться → «На экран «Домой»».
- **ПК / Chrome, Edge:** значок установки в адресной строке.

Service worker собирается только для продакшн-сборки (`npm start`), чтобы не мешать разработке.
Со своим движком оффлайн играется целиком: ходы считаются в браузере.

## Где что лежит

```
src/          ядро — изоморфное, без fs/path/process
  engine.ts     единственная точка изменения состояния: applyDelta, разбитая по разделам
  tuning.ts     настройка вкуса партии и защитный разбор
  golden.ts     эталонные состояния и прогон по ним
  session.ts    контур хода: рассказчик, ретрай, двухфазный ход, откат
  narrator/     свой движок повествования
  storage/      адаптер хранилища: indexeddb (браузер), fs (CLI/тесты), memory
  ui/           React-оболочка: экраны, компоненты, 2D-сцена. Игровой логики нет
server/       прокси к LLM и его замки (llm-guard.ts) — и больше ничего
prompt/       CORE.md и DELTA-SCHEMA.md уходят в модель; INIT.md — только для инициации
packs/        сеттинги — обычные JSON той же формы, что state.example.json
test/         регрессия ядра, своего движка, прокси и эталонного прогона
```

## Как добавить свой сеттинг

Скопируйте `packs/grauberg.json`, правьте содержимое, положите рядом под своим именем.
Пак появится на экране выбора сам: имя файла — это id пака, код не трогается.
Негодный файл не роняет приложение — показывается список причин.

Обязательное в паке: `meta` (персонаж, сеттинг, валюта, жёсткость), `economy.anchors`,
хотя бы один фронт с `advanceCondition`, хотя бы один NPC и хотя бы один пункт `unknowns`.
Необязательное, но полезное: блок `tuning` — правила, с которыми мир задуман.
Свой движок подхватит новый мир без единой строчки кода: вкус он определит по описанию,
цены — по вашим якорям.

## Как устроен ход

1. Игрок выбирает действие в колоде, нажимает человека в кадре или пишет своими словами.
2. Локальные команды (снапшот, аудит, лог, цены, откат, экспорт) выполняются кодом.
3. Рассказчик получает состояние, факты прошлого хода и требования календаря.
4. Возвращаются проза и дельта.
5. `applyDelta` — единственное место, где меняются числа. Отклонённое становится фактом мира.
6. Состояние сохраняется в IndexedDB, предыдущее — в стек отката (20 шагов).

Просроченный срок не висит декорацией: он идёт тремя ступенями — косвенный сигнал, прямая
угроза, мир действует сам, — и на третьей движок сам добавляет расплату, роняет отношение
кредитора и пишет прецедент. Требования движка гаснут: если рассказчик не отработал одно
и то же за отведённое число ходов, требование снимается, а вопрос мир решает без него.

## Приватность и безопасность

Со своим движком наружу не уходит ничего: ни состояния, ни текста, ни запросов.

С моделью ключ хранится только в `localStorage` браузера и уходит ровно в тот эндпоинт,
который вы указали, транзитом через локальный прокси. Прокси не логирует ни ключ, ни тела
запросов и ничего не хранит. Кроме этого у него три замка (`server/llm-guard.ts`):

- **белый список адресов** — известные эндпоинты плюс своя машина; расширяется переменной
  `LLM_ALLOWED_HOSTS` (через запятую, поддерживает `*.example.com`), режим `LLM_LOCAL_ONLY=1`
  оставляет только локальные модели;
- **запрет внутренних диапазонов** — `10/8`, `172.16/12`, `192.168/16`, `169.254/16`, CGNAT,
  `fc00::/7`, `fe80::/10`, адреса метаданных облака. Работает даже против белого списка;
- **проверка источника** — прокси обслуживает только собственную страницу, чужой `origin`
  и `sec-fetch-site: cross-site` получают отказ.

Плюс сервер и Vite по умолчанию слушают `localhost`, а не все интерфейсы.

## Reasoning-модели

Часть моделей отвечает ошибкой на параметр температуры. Клиент делает один автоматический
повтор без спорного параметра и запоминает отказ на всю сессию — по тому же образцу, что
и повтор при отказе от структурного вывода. Настраивать ничего не нужно.

## Двухфазный ход

Тумблер в настройках для игры с моделью: первый запрос отдаёт только дельту, движок считает
её результат, второй запрос пишет прозу по уже применённому состоянию. Убирает класс багов
«проза описала то, что движок отклонил». Цена — два запроса на ход. Своему движку не нужен:
он и так видит результат до того, как пишет.

## Эталонный прогон

```bash
npm run golden          # первый пак, восемь ходов на состояние
npm run golden ringen 12
```

Десять состояний, каждое из которых что-то ломало: свежий старт, старая просрочка, пустая
касса, смертельная причина в теле, правило шрама, истощение, фронт на пороге, пустой реестр
неустановленного, гора обещаний и мир, о котором движок ничего не знает. Прогон отвечает на
четыре вопроса про любого рассказчика: отрабатывает ли он требования движка, двигает ли время,
не выдумывает ли чисел, не просит ли невозможного. Тем же прогоном можно мерить и модель за
ключом — он принимает любого рассказчика той же формы.

## Голосовой ввод

Кнопка 🎤 рядом с полем ввода. Два режима, выбираются в Настройках (по умолчанию — авто):

1. **Браузером** (Web Speech API) — бесплатно, без токенов, с черновиком по ходу речи. Chrome и Safari.
2. **На эндпоинте** (`POST /audio/transcriptions`, модель `whisper-1` по умолчанию) — запись через
   `MediaRecorder`, уходит через тот же локальный прокси, тратит квоту. Фолбэк для Firefox
   и только для игры с ключом.

Правило: **голос никогда не отправляет ход сам** — только наполняет поле ввода. Исключение одно:
если поле пусто и сказана локальная команда («снапшот», «аудит», «команда откат») — она выполняется
сразу: рассказчик не задет, состояние не портится.

Диктуемая пунктуация работает только в конце фразы («иду к гавани точка» → «иду к гавани.»), чтобы
не сломать «точка сборки у маяка». Отдельно есть тумблер «читать прозу вслух» (`speechSynthesis`).

Границы, о которых надо знать: микрофон требует https или localhost; в Safari/iOS речь уходит на
серверы Apple, в Chrome — Google; Web Speech обрывается на длинных паузах — нажмите микрофон снова.
