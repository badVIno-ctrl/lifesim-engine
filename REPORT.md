## 2. Изменённые тесты (из исходных 25)

Изменено **два**. Остальные 23 перенесены буквально.

### 2.1. «касса не уходит в минус» (№ 4)

Было: проверял `warnings.length > 0`.
Стало: проверяет `hasCode(facts, "money_insufficient")` и текст факта с двумя числами.

**Почему.** Пункт A: отклонение больше не «предупреждение для лога», а типизированный факт мира с кодом,
который уходит модели следующим сообщением. `warnings` остались как `facts.map(f => f.text)` — старое поведение
не сломано, но проверять по длине массива строк теперь бессмысленно: важен код и то, что факт помечен `forModel`.

### 2.2. «веха и озарение требуют критерия из списка» (№ 14)

Было: один тест на две сущности — веху и шкалу озарения.
Стало: «веха требует критерия из списка»; половина про критерии переехала в три теста `engine.v14.test.ts` про перелом.

**Почему.** Пункт B: поля `insight` больше нет ни в `State`, ни в `Delta` — тест не мог компилироваться в прежнем виде.
Поведенческая часть не ослаблена, а усилена: вместо одной проверки теперь четыре (веха + три на перелом).

Что **не** трогали: остальные 23 теста работают без единой правки, включая № 25 (детерминизм и отсутствие мутации входа)
и № 18 (ротация каналов). Адаптация свелась к импортам из `./helpers.ts`.

- `engine.v14`: добавление пункта сбрасывает счётчик `lastUnknownAddTurn`.

### G. Режим отладки

- `session`: рядом с ходом сохранены сырая дельта, список применённого, список отклонённого с кодами, токены, модель, флаг ретрая.
- `session`: в ленту игрока попадает только проза — ни `<delta>`, ни фигурных скобок.

### H. Сжатие контекста

- `session`: в запрос уходят CORE + схема + компактный рендер состояния + реплика игрока.
- `session`: из 20 сообщений истории уходят ровно последние 8.
- `session`: на 7-м ходу код сам делает снапшот и урезает переписку до двух сообщений.
- `session`: команда «снапшот» выполняется кодом и не ходит в модель.
- `init`: `CORE.md` укладывается в 2000 слов (фактически ~815).

### I. Контент-паки

- В `packs/` не менее двух паков; состояние каждого проходит `audit()` и годится для первого хода.
- Новый источник подхватывается тем же кодом — проверка, что добавление пака не требует правки кода.
- Негодный пак даёт список причин, а не стектрейс.
- Состояние из пака не связано ссылками с самим паком (две партии не портят друг друга).
- Порядок паков устойчив между запусками.

### J. Устойчивость к слабым моделям

- `session`: невалидный JSON → ровно один ретрай, второй ответ принимается.
- `session`: два негодных ответа → состояние не сдвинулось, игроку внятный текст.
- `session`: сетевая ошибка (401) → состояние байт в байт то же, сообщение человеческое.
- `session`: ответ по json_schema принимается без парсинга `<delta>`.
- `schema` (6 тестов): схема собрана из `DELTA_KEYS`, все узлы закрыты от лишних полей, шаги ограничены ±3, абсолютных чисел нет.

### Архитектурные тесты

- `init`: ядро изоморфно — ни один файл в `src/*.ts` не импортирует `node:*`, не трогает `process` и `require`.
- `init`: `INIT.md` не импортируется ни клиентом, ни контуром хода — в контекст игры он попасть не может физически.
- `storage`: обе реализации прогоняются по одному контракту, чтобы IndexedDB и fs не разъехались.

## 4. Почему оставшиеся правила всё ещё живут в тексте промпта

Правило: что можно проверить кодом — проверяется кодом. В `CORE.md` остались только требования
к **тексту**, а текст не проходит через `applyDelta`:

| Правило в тексте | Почему не проверяется в коде |
| --- | --- |
| 150–350 слов, настоящее время, второе лицо | свойство прозы. Формально считать слова можно, но реакция на нарушение — только ретрай, а ретрай разрешён ровно один, и только для битого JSON (пункт A) |
| ни одного числа в прозе | число в реплике персонажа законно (торг). Отличить легальное от утечки состояния регуляркой нельзя без ложных срабатываний |
| хотя бы один канал восприятия кроме зрения | код проверяет то, что проверяемо: поле `channel` обязательно и ротация каналов контролируется. А вот есть ли заявленный запах в самом тексте — вопрос смысла, не структуры |
| не называть ступени лестниц вслух | то же самое: слово «на грани» бывает обычной речью |
| игрок заявляет попытку, результат решает рассказчик | это распределение ролей, а не операция над состоянием |
| не выдавать ответы на пункты `unknowns` | код проверяет факт пополнения реестра и толкает директивой (F), но понять, что абзац прозы раскрыл тайну, может только читатель |
| формат ответа (проза, затем один `<delta>`) | это инструкция до вызова; код проверяет её постфактум в `parseTurn` и штрафует ретраем |

Всё остальное из старого `CORE.md` выброшено именно потому, что его теперь держит код:
лимиты, ступени, сроки, снапшоты, микро-лог, сверка, рутина по расписанию, условия фронтов, порог перелома.
Объём: было 340 слов в v13 плюс разбросанные правила → стало 815 слов цельного CORE и 643 слова схемы,
при этом из текста ушли все численные регламенты.
